title: 主流 AI Agent 对比
description: 国内外编码 Agent 的模型能力、Agent 架构与生态横向对比，以及选型依据
---

"AI Agent"这个词被用得太泛。这篇笔记把范围收窄到**能读代码、改代码、跑命令的编码 Agent**，从三个维度横向对比：**模型能力**（底座）、**Agent 架构**（怎么把模型变成会干活的系统）、**生态**（工具链、集成与可用性）。

先说结论：**国外赢在前沿模型与生态先发，国内赢在本地化、合规私有化与成本**。但两者正在互相渗透——开源模型已经能接上类 Claude Code 的脚手架。

## 维度一：模型能力

<Callout type="warn" title="基准数字务必看口径">
  第三方聚合榜之间**互相打架**：同一模型在不同榜单能差出十几个百分点（scaffold 脚手架、prompt、评测规模都不同）。**只引用厂商官方 system card 里的数字**，聚合榜仅作趋势参考。
</Callout>

- **SWE-bench Verified**（修真实 issue）：前沿闭源模型已进入 90%+ 区间；但第三方榜对同一模型的报数从 79% 到 96% 不等，口径混乱。
- **Terminal-Bench 2.0**（终端自主操作）：国外头部约 82%，国产开源模型在 50% 出头——**差距主要体现在长链路自主性与工具使用稳定性**上。
- **长上下文**：国外 Claude 系与国产 DeepSeek-V 系都主打 **1M token**，这是国产缓解"上下文管理弱"的主要手段。

一句话：**榜单领先看国外，但真实差距高度依赖你的任务形态**——修单文件 bug 与跨仓库重构，考验的能力完全不同。

## 维度二：Agent 架构

这是最能体现"工程功力"的维度，四个子问题：

1. **编排（单 Agent vs 多 Agent）**
   主流正从"单 agent 循环"走向"多 agent 编排"：Claude Code 的动态工作流、Kimi 的 Agent Swarm、Coze 3.0 的多人多 Agent、Devin 的 Fusion 架构、Qoder 的多智能体协同。**多 Agent 的代价是调试与成本**，不是越多越好。
2. **上下文管理**（决定能跑多久）
   Claude Code 的做法有代表性：`/compact` 自动压缩 + `.claude/agents/*.md` 子代理隔离 + 项目记忆文件落盘；子代理还能再生成子代理，但受**深度/并发/花费上限**约束。国产普遍用"堆长上下文"（1M）替代精细压缩——简单，但长任务里更容易衰减。
3. **工具系统 / MCP**
   **MCP 已是事实标准**：2026 年主流厂商（Anthropic、OpenAI、Google、Microsoft、AWS、Cursor、JetBrains、LangChain 等）原生支持，规范也在持续大版本迭代。配套的 **A2A**（Agent 间通信）在并行推进。对团队的含义：**把内部工具做成 MCP Server，一次投入、所有 Agent 复用**。
4. **沙箱与权限**（企业落地的门槛）
   Claude Code：OS 级文件/网络隔离 + 权限规则 + hooks（可强制网络白名单）；Codex：sandbox + approvals 双层；国产企业版（CodeBuddy 等）加入运行时安全检测。**没有沙箱的 Agent 不要接入生产仓库**。

## 维度三：生态与可用性

- **形态**：国外以 **CLI / Cloud / SDK** 为主（SDK、CLI 开源），偏"可编程、可组合"；国内普遍是 **IDE 插件 + 独立 IDE + CLI 三端齐上**，偏"开箱即用"。
- **私有化与合规**：**国内显著强于国外**——Dify 支持 on-prem、Qoder 企业专属版走专属 VPC、CodeBuddy 有专有云企业版、智谱 GLM 适配国产芯片。数据不出内网这一条，在国外产品上很难满足。
- **可用性**：国外头部（Claude Code、Codex、Antigravity、Devin）对国内用户**直连受限**；国产企业版价格据评测约为海外同级的一半左右（二手数据，需自行核实）。
- **开放性**：开源组合正在打通——**开源模型（DeepSeek / Kimi / GLM）+ 类 Claude Code 脚手架**（含各种兼容层）已经可用，选型不再等于"选厂商"。

## 选型依据

| 你的约束 | 倾向 |
| --- | --- |
| 要最前沿的自主能力、可编程工作流 | 国外头部（Claude Code / Codex / Antigravity） |
| 强合规、数据不出内网、中文场景 | 国内（Qoder CN / CodeBuddy / Dify 私有化） |
| 成本敏感、想自建 | 开源模型 + 开源脚手架（Aider / Cline / OpenHands） |
| 只要 PR 审查 / 单测生成 | CodeRabbit / Greptile / Diffblue 这类单点工具 |

## 三点判断

1. **模型差距在缩小，架构差距在放大**。同样的模型，好的上下文管理与子代理隔离能让完成率差出数倍——**架构是可积累的工程资产，模型不是**。
2. **MCP 是当下最值得投入的接口层**。它把"给 Agent 提供上下文/工具"从每家一套变成一次接入、到处复用。
3. **合规不是减分项**。数据不出内网、沙箱与权限模型，正在从"国内特色"变成**全球企业采购的硬门槛**。
