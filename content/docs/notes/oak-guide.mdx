Oak（`oakserver/oak`）是一个受 Koa 启发的 HTTP 中间件框架。它最初为 Deno 而生，现在同一份代码可以跑在 Deno、Node.js、Bun 和 Cloudflare Workers 上。本文基于 **v17.2.0**，只讲日常开发真正会用到的部分。

<Callout type="info" title="选型前提">
  Oak 只提供"中间件 + 路由 + 上下文"这一层，不包含 ORM、模板引擎和鉴权方案。它适合想显式控制 HTTP 流程、又不愿引入 Express 那套插件体系的项目。如果只是一个极简的 `fetch` 处理函数，原生 `Deno.serve` 更省事。
</Callout>

## 安装与最小服务

Deno 下不必安装依赖，直接从 JSR 引入：

```ts
// main.ts
import { Application } from "jsr:@oak/oak/application";
import { Router } from "jsr:@oak/oak/router";

const router = new Router();
router.get("/", (ctx) => {
  ctx.response.body = { message: "Hello oak!" };
});

const app = new Application();
app.use(router.routes());
app.use(router.allowedMethods());

await app.listen({ port: 8000 });
```

Node.js / Bun 下先装包，再把导入路径换成包名：

```bash
npm i @oak/oak
# 或
bun add @oak/oak
```

```ts
import { Application } from "@oak/oak/application";
import { Router } from "@oak/oak/router";
```

运行：

```bash
deno run --allow-net main.ts
# 或
bun run main.ts
```

访问 `http://localhost:8000`，应返回 `{"message":"Hello oak!"}`。给 `ctx.response.body` 赋对象时，Oak 会自动序列化为 JSON 并设置对应的 `Content-Type`。

## 中间件与洋葱模型

中间件签名固定为 `(ctx, next) => Promise<void>`。`await next()` 之前的代码在外层、之后的代码在内层，形成 Koa 式的"洋葱"：

```ts
import type { Middleware } from "jsr:@oak/oak/middleware";

const timing: Middleware = async (ctx, next) => {
  const start = performance.now();
  await next(); // 交棒给下游
  const cost = (performance.now() - start).toFixed(1);
  ctx.response.headers.set("X-Response-Time", `${cost}ms`);
};
```

三条最容易踩的规则：

- **必须 `await next()`**，否则后面的中间件和路由都不会执行。
- 中间件按 `app.use()` 的注册顺序进入，按相反顺序退出。
- 越靠前的中间件越"外层"，错误处理要放在最前面。

## 路由

### 基础与路径参数

```ts
const router = new Router();

router.get("/users/:id", (ctx) => {
  ctx.response.body = { id: ctx.params.id }; // 注意：永远是字符串
});

router.post("/users", async (ctx) => {
  if (!ctx.request.hasBody) ctx.throw(400, "缺少请求体");
  const payload = await ctx.request.body.json();
  ctx.response.status = 201;
  ctx.response.headers.set("Location", "/users/1");
  ctx.response.body = payload;
});
```

### 分组与挂载

```ts
const api = new Router({ prefix: "/api" });
api.get("/health", (ctx) => {
  ctx.response.body = { ok: true };
});

const app = new Application();
app.use(api.routes(), api.allowedMethods());
```

`allowedMethods()` 负责处理 `OPTIONS`、`405 Method Not Allowed` 和 `501 Not Implemented`。**它必须和 `routes()` 一起挂载，且放在后面**，否则预检和错误方法会落到默认 404。

多个子路由可以嵌套挂载：

```ts
const users = new Router({ prefix: "/users" });
users.get("/:id", (ctx) => {
  ctx.response.body = { id: ctx.params.id };
});

const root = new Router();
root.use(users.routes(), users.allowedMethods());
root.get("/", (ctx) => {
  ctx.response.body = "home";
});
```

### 单条路由挂多个中间件

```ts
const auth: Middleware = async (ctx, next) => {
  const header = ctx.request.headers.get("authorization");
  if (!header?.startsWith("Bearer ")) ctx.throw(401, "未提供令牌");
  // 这里换成真实的校验逻辑
  ctx.state.user = { id: "1", name: "yin" };
  await next();
};

router.get("/me", auth, (ctx) => {
  ctx.response.body = ctx.state.user;
});
```

### 命名路由与反向生成 URL

```ts
router.get("user", "/users/:id", (ctx) => {
  ctx.response.body = { id: ctx.params.id };
});

router.url("user", { id: "42" }); // "/users/42"
```

## 上下文（ctx）常用能力

`ctx` 是每次请求独有的对象，主要分四块：

| 属性 | 用途 |
| --- | --- |
| `ctx.request` | 方法、URL、请求头、请求体 |
| `ctx.response` | 状态码、响应头、响应体 |
| `ctx.state` | 中间件之间共享数据的容器 |
| `ctx.cookies` | 读写 Cookie |

常用的快捷方法：

```ts
ctx.throw(403, "没有权限");   // 抛出一个带状态码的错误
ctx.assert(user, 401, "请先登录"); // 条件不成立时抛出
ctx.response.redirect("/login");   // 302
ctx.request.ip;                    // 客户端地址（需 app.proxy 才信任代理头）
```

`ctx.throw` 抛出的错误如果没人捕获，会被 Oak 转成对应状态码的响应；想统一格式，就在最外层用中间件捕获。

## 请求体

Oak v17 的请求体 API 已对齐 Fetch 标准，`ctx.request.body` 是一个对象而不是函数：

```ts
// JSON
const data = await ctx.request.body.json();

// 纯文本
const text = await ctx.request.body.text();

// application/x-www-form-urlencoded
const form = await ctx.request.body.form(); // URLSearchParams
const name = form.get("name");

// multipart/form-data（文件上传）
const fd = await ctx.request.body.formData();
const file = fd.get("file") as File;

// 原始数据
const buf = await ctx.request.body.arrayBuffer();
```

请求体是流，**只能消费一次**。读完一次再读会报错，可以用 `ctx.request.body.used` 判断是否已被读过。需要"先校验再解析"时，先存到变量里。

## 响应与错误处理

```ts
ctx.response.status = 200;
ctx.response.type = "text/html";        // 设置 Content-Type
ctx.response.headers.set("X-Trace-Id", id);
ctx.response.body = "<h1>hi</h1>";

// 直接给 Response 也可以
ctx.response.body = new Response("ok", { status: 202 });
```

统一错误处理放在最外层，保证任何下游抛错都返回同一结构：

```ts
const errorHandler: Middleware = async (ctx, next) => {
  try {
    await next();
  } catch (err) {
    const status = (err as { status?: number }).status ?? 500;
    ctx.response.status = status;
    ctx.response.body = {
      code: status,
      message: status === 500 ? "服务器内部错误" : (err as Error).message,
    };
    if (status === 500) console.error(err);
  }
};

app.use(errorHandler); // 必须第一个注册
```

没有中间件设置响应体时，Oak 默认返回 `404 Not Found`。

## 静态文件

```ts
import { send } from "jsr:@oak/oak/send";
import { fromFileUrl } from "jsr:@std/path/from-file-url";

const root = fromFileUrl(new URL("./public/", import.meta.url));

app.use(async (ctx, next) => {
  try {
    await send(ctx, ctx.request.url.pathname, {
      root,
      index: "index.html",
    });
  } catch {
    await next(); // 文件不存在时交给后续路由
  }
});
```

`send` 需要 `--allow-read` 权限。Windows 下务必用 `fromFileUrl` 转换，直接拼 `import.meta.url` 会得到 `file:///` 前缀导致路径失效。Node 环境请改用 `node:path` 的 `fileURLToPath`。

## Cookie 与签名

```ts
const app = new Application({ keys: ["change-me-in-production"] });

ctx.cookies.set("session", token, {
  httpOnly: true,
  sameSite: "lax",
  secure: true,
  maxAge: 60 * 60,
});

const token = ctx.cookies.get("session");
```

设置 `keys` 后，`ctx.cookies.set(..., { signed: true })` 会用密钥签名，读取时自动校验；不设 `keys` 则无法使用签名 Cookie。生产环境密钥应从环境变量读取，不要写进代码。

## 测试

Oak 自带 `testing` 模块，可以脱离 HTTP 服务直接调用中间件：

```ts
import { createMockContext, createMockNext } from "jsr:@oak/oak/testing";
import { assertEquals } from "jsr:@std/assert";

Deno.test("GET /health 返回 ok", async () => {
  const ctx = createMockContext({ method: "GET", path: "/health" });
  await health(ctx, createMockNext());

  assertEquals(ctx.response.status, 200);
  assertEquals(ctx.response.body, { ok: true });
});
```

`createMockContext` 支持设置 `method`、`path`、`params`、`headers`、`state`、`body` 等字段，足够覆盖大部分中间件逻辑。需要走完整路由栈时，可以起一个临时端口发真实请求，或使用社区里的 `superoak`（注意它对新版本 Oak 的兼容性）。

## 部署

**Deno Deploy / Cloudflare Workers** 直接导出 `fetch`：

```ts
export default { fetch: app.fetch };
```

**Node.js / Bun** 保持 `await app.listen({ port })`，端口从环境变量读取：

```ts
await app.listen({ port: Number(Deno.env.get("PORT") ?? 8000) });
```

Bun 下把 `Deno.env` 换成 `process.env` 即可。

<Callout type="warn" title="跨运行时注意">
  代码里用到 `Deno.env`、`Deno.errors`、`fromFileUrl` 等 Deno 专有 API 时，这份代码就无法直接跑在 Node/Cloudflare。要么把这些隔离到适配层，要么只用 Web 标准 API。
</Callout>

## 常见坑

- **忘了 `allowedMethods()`**：`OPTIONS` 预检和错误方法都返回 404。
- **忘了 `await next()`**：请求"卡"在当前中间件，表现像路由没注册。
- **中间件顺序颠倒**：错误处理放到最后，等于没写。
- **重复读取请求体**：第二次 `body.json()` 直接抛错。
- **把 `ctx.params` 当数字**：它一定是字符串，比较前先转换。
- **静态文件抢路由**：`send` 放在业务路由前，可能把 API 路径当文件名解析，建议按前缀分流。
- **`app.proxy` 未开启**：反向代理后面拿到的 `ctx.request.ip` 是代理地址。

## 小结

Oak 的心智模型很小：**一个应用、一组中间件、一棵路由**。掌握 `next()` 的洋葱顺序和 `ctx` 的三块状态（request / response / state），剩下的就是查 API。它的优势在于类型完整、与 Web 标准对齐、跨运行时；代价是生态规模远小于 Express，很多东西要自己写中间件。

如果项目本来就是"边缘部署 + 极致轻量"，Hono 可能更合适；如果是 Deno 原生项目、又想要 Koa 式的可控流程，Oak 是很稳的选择。
